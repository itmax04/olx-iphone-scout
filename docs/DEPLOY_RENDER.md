# Публикация на Render.com (Blueprint)

Render — облачный хостинг, где приложение работает круглосуточно без вашего
Mac. Развертывание описано в файле `render.yaml` (Blueprint): веб-сервис
(`web`), фоновый воркер (`worker`) и управляемая база PostgreSQL 17, регион
`frankfurt`. Секреты в `render.yaml` помечены `sync: false` — это значит, что
их значения **не лежат в репозитории**, а вводятся вручную в панели Render.
`DATABASE_URL` подставляется автоматически из созданной базы (`fromDatabase`).

Важно: Render — платный (web + worker + PostgreSQL). **Платный деплой
запускает только владелец, вручную.** Ни один скрипт и ни одна инструкция
из этого репозитория не создает платных ресурсов сама.

## Шаг 0. Предусловия

- Локально все работает: фикстурная приемка `FIXTURE_PIPELINE=PASS`, тесты
  проходят, Telegram протестирован (см. RELEASE_CHECKLIST.md).
- Код лежит в **приватном** репозитории GitHub, `.env` не закоммичен.
- Свежий локальный бэкап сделан (docs/BACKUP_RESTORE.md).

## Шаг 1. Аккаунт Render

1. Зарегистрируйтесь на https://render.com (удобно через GitHub).
2. Включите 2FA в настройках аккаунта.
3. Привяжите платежную карту (Billing) — сервисы платные.

## Шаг 2. Подключите репозиторий

1. В панели Render: New → Blueprint.
2. Разрешите Render доступ к GitHub и выберите ваш приватный репозиторий
   (можно выдать доступ только к нему одному).
3. Render найдет `render.yaml` в корне и покажет план: сервисы `web`,
   `worker` и база PostgreSQL 17 в регионе frankfurt.

## Шаг 3. Введите секреты (sync: false)

Перед нажатием Apply Render попросит значения переменных, помеченных
`sync: false`. Введите:

- `DJANGO_SECRET_KEY` — **новый** ключ, не тот, что локально:

```bash
openssl rand -hex 48
```

- `ADMIN_USERNAME`, `ADMIN_EMAIL` — как локально;
- `ADMIN_PASSWORD` — **новый** одноразовый пароль (сразу после первого входа
  смените его в интерфейсе):

```bash
openssl rand -hex 12
```

- `OPENAI_API_KEY` — можно оставить пустым на первый деплой (AI все равно
  выключен);
- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` — ваши значения из
  docs/TELEGRAM_SETUP.md (бот один и тот же для локальной и облачной версии).

`DATABASE_URL` вводить не нужно — Render подставит его из своей базы.
Проверьте, что в переменных первого деплоя `MONITOR_ENABLED=false` и
`AI_ENABLED=false` — включать мониторинг будем в самом конце.

## Шаг 4. Apply и первый деплой

Нажмите Apply. Render создаст базу, соберет Docker-образ (10–20 минут первый
раз), выполнит миграции и `bootstrap_admin`, запустит `web` и `worker`.
Дождитесь статуса `Live` у обоих сервисов.

При ошибке сборки/старта: откройте вкладку Logs упавшего сервиса; типовые
причины — незаполненный секрет или опечатка в значении.

## Шаг 5. Проверка health и вход

URL сервиса вида `https://<имя>.onrender.com` виден в панели.

```bash
curl -s https://<имя>.onrender.com/api/v1/health/live/
```

```bash
curl -s https://<имя>.onrender.com/api/v1/health/ready/
```

Ожидаемый результат: HTTP 200 и JSON со статусом ok у обоих.

Затем откройте `https://<имя>.onrender.com` в браузере, войдите
(`ADMIN_USERNAME` / `ADMIN_PASSWORD` из шага 3) и **сразу смените пароль** на
`/accounts/password_change/`.

## Шаг 6. Первый smoke-тест (мониторинг еще выключен)

1. /system/ — воркер `HEALTHY`.
2. /settings/ — «Отправить тест Telegram» → сообщение пришло.
3. /searches/ — создайте один реальный поиск (docs/USER_GUIDE.md).
4. /prices/ — заведите рыночную цену для целевой модели.

## Шаг 7. Включение мониторинга — в самом конце

Только когда все проверки шага 6 пройдены:

1. В панели Render: сервисы `web` и `worker` → Environment →
   `MONITOR_ENABLED=true` → Save (Render перезапустит сервисы).
2. Через 5–10 минут проверьте /runs/ — появились запуски со статусом
   `SUCCESS`; /dashboard/ — появляются объявления.
3. AI (по желанию) включайте еще позже, по docs/OPENAI_SETUP.md
   (`AI_ENABLED=true` + галочка на /settings/).

## Откат и восстановление

- **Код**: в панели Render у сервиса есть список деплоев и кнопка
  **Rollback** — мгновенный возврат на предыдущий образ. Используйте, если
  новая версия сломалась.
- **Данные**: у базы Render есть **PITR** (point-in-time recovery) —
  восстановление на момент времени в панели Database → Recovery. Подробнее и
  про локальные дампы — docs/BACKUP_RESTORE.md.

## Обновление версии на Render

Push в подключенную ветку GitHub запускает автодеплой (если включен) либо
деплой запускается вручную кнопкой Manual Deploy. Миграции выполняются
автоматически до переключения трафика. Перед крупными обновлениями — дамп
базы.
