# Подключение AI-анализа (OpenAI)

AI-анализ — **необязательная** функция. Приложение полностью работает и без
нее: детерминированная оценка (распознавание модели/памяти, расчет прибыли
profit-v1, пороги кандидата) не использует OpenAI вообще. AI добавляет сверху
анализ текста объявления: риски («восстановленный», «icloud lock», «копия»),
упомянутые дефекты, оценку уверенности.

Это единственная платная внешняя услуга. Прежде чем включать — прочитайте
раздел про лимиты.

## Шаг 1. Создайте project-scoped ключ

1. Зарегистрируйтесь/войдите на https://platform.openai.com .
2. Создайте отдельный **проект** (например, «iphone-scout») в разделе
   Projects — не используйте ключ «на весь аккаунт».
3. В проекте создайте API-ключ (Project API key). Скопируйте его сразу —
   больше он не показывается. Ключ — секрет: не пересылайте и не коммитьте.

## Шаг 2. Настройте billing и лимиты на стороне OpenAI

1. В разделе Billing привяжите карту и пополните баланс на небольшую сумму
   (5–10 $ хватит надолго).
2. Обязательно установите **месячный бюджет-лимит** в настройках OpenAI
   (Budget limit) — это ваша вторая линия защиты от неожиданных расходов.

## Шаг 3. Впишите ключ в `.env`, но AI пока не включайте

```
OPENAI_API_KEY=<ваш-project-ключ>
AI_ENABLED=false
```

`AI_ENABLED=false` оставьте до тех пор, пока не пройдена фикстурная приемка
(`run_fixture_pipeline` → `FIXTURE_PIPELINE=PASS`, см. docs/LOCAL_SETUP.md,
раздел 6) и вы не убедились, что мониторинг и Telegram работают. Не платите
за анализ, пока базовый конвейер не проверен.

## Шаг 4. Лимиты расходов приложения (обязательный circuit breaker)

В `.env` уже заданы жесткие лимиты самого приложения:

```
AI_DAILY_HARD_LIMIT_USD=1.00
AI_MONTHLY_HARD_LIMIT_USD=10.00
```

Это **обязательный предохранитель**: перед каждым обращением к OpenAI
приложение суммирует фактические расходы за день и за месяц (по количеству
токенов и ценам из `OPENAI_*_USD_PER_MILLION`), и если лимит достигнут —
запрос к OpenAI просто не выполняется («Дневной лимит расходов AI исчерпан» /
«Месячный лимит...»). Объявление при этом все равно проходит детерминированную
оценку — вы не теряете кандидатов, теряется только AI-комментарий.

Не отключайте и не завышайте лимиты «на всякий случай»: значения по умолчанию
рассчитаны на реальный поток объявлений. Расходы за месяц видны на /dashboard/.

Раз в квартал сверяйте цены моделей на сайте OpenAI со значениями
`OPENAI_FAST_INPUT_USD_PER_MILLION` и остальными и обновляйте
`OPENAI_PRICING_VERIFIED_AT` — от этих цифр зависит точность предохранителя.

## Шаг 5. Проверка конфигурации без трат

После заполнения ключа перезапустите контейнеры:

```bash
docker compose up -d --force-recreate web worker
```

Затем на странице /settings/ нажмите **«Проверить OpenAI-конфигурацию»**.
Ожидаемый результат: сообщение «Конфигурация OpenAI: настроена (fast: ...,
deep: ...); provider не вызывался» — проверка не делает платных запросов.

## Шаг 6. Включение AI

Только после фикстурной приемки:

1. В `.env`: `AI_ENABLED=true`, затем:

```bash
docker compose up -d --force-recreate web worker
```

2. На /settings/ включите галочку «AI-анализ включен». AI работает только
   когда включены **оба** переключателя: переменная окружения `AI_ENABLED`
   и галочка в настройках. Выключить AI мгновенно можно любой из них
   (галочка — без перезапуска).

## Как работает fast/deep

- Каждое подходящее объявление сначала анализирует **быстрая (fast) модель**
  (`OPENAI_FAST_MODEL`) — дешевая, для массового потока.
- Если fast-модель не уверена (уверенность ниже порога «Порог уверенности для
  deep AI» на /settings/) или объявление особо выгодно (ожидаемая прибыль выше
  порога «Особо выгодно, грн»), анализ эскалируется на **глубокую (deep)
  модель** (`OPENAI_DEEP_MODEL`) — дороже, но точнее.
- Ответ модели принимается только по строгой JSON-схеме; произвольный текст
  модели никуда не попадает и решения не принимает.
- Результаты кэшируются: повторный анализ того же текста не оплачивается
  заново; кнопка «Повторить AI-анализ» в карточке ставит объявление в очередь
  принудительно.

## Что будет, если AI недоступен

Если OpenAI вернул ошибку, ключ невалиден, деньги кончились или сработал
лимит приложения — **мониторинг продолжает работать полностью**:
объявления собираются, дедуплицируются, прибыль считается, кандидаты
отбираются, уведомления отправляются. У объявления просто будет пометка, что
AI-анализ не выполнен (`FAILED`/заблокирован бюджетом), и его можно повторить
позже кнопкой «Повторить AI-анализ».

## Ротация ключа

Раз в 90 дней (или при малейшем подозрении на утечку): создайте новый ключ в
том же проекте OpenAI → замените `OPENAI_API_KEY` в `.env` →
`docker compose up -d --force-recreate web worker` → удалите старый ключ на
platform.openai.com.
