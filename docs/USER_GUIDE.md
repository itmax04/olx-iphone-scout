# Руководство пользователя

Приложение открывается по адресу http://localhost:8000 (или по адресу вашего
Render-сервиса). Все страницы доступны только после входа администратором.

Главный принцип: **приложение никогда не пишет продавцам, не звонит, ничего
не покупает и не продает**. Оно собирает публичные объявления, считает цифры
и присылает уведомления. Каждое решение — написать продавцу, купить, продать —
принимаете вы, вручную, вне приложения.

## Карта страниц

| Адрес | Название | Для чего |
|---|---|---|
| `/dashboard/` | Дашборд | Сводка дня: кандидаты, ошибки, воронка, расходы AI |
| `/searches/` | Поиски | Сохраненные поисковые URL OLX и их настройки |
| `/listings/` | Объявления | Все найденные объявления, фильтры, карточка с историей цен |
| `/prices/` | Цены | Рыночные цены перепродажи и резервы на дефекты |
| `/deals/` | Сделки | Учет покупок/продаж и фактическая прибыль |
| `/runs/` | Запуски | Журнал сканирований (успех/ошибки/блокировки) |
| `/settings/` | Настройки | Пауза/возобновление, AI-настройки, тест Telegram |
| `/system/` | Система | Диагностика: воркер, heartbeat, очистка данных |
| `/admin/` | Django-админка | Аварийный доступ к «сырым» данным; в обычной работе не нужна |

Health-эндпоинты (для скриптов и Render): `GET /api/v1/health/live/` и
`GET /api/v1/health/ready/`.

## /dashboard/ — Дашборд

Что видно:

- статистика за сегодня (найдено, кандидатов);
- список свежих кандидатов — быстрые ссылки в карточки объявлений;
- последние ошибки сканирования;
- «просроченные» поиски (давно не сканировались);
- воронка статусов (сколько объявлений в каждом статусе);
- расходы AI за текущий месяц.

Типовой сценарий: заходить сюда утром — если есть новые кандидаты, открывать
их карточки и принимать решение.

## /searches/ — Поиски

Поиск (поисковый профиль) — это сохраненный URL выдачи OLX плюс ваши пороги
прибыльности. Воркер регулярно сканирует каждый активный поиск.

Кнопки списка: «Создать», «Редактировать», «Запустить сейчас», включение/
выключение (переключатель активности), «Архивировать».

### Как создать поиск

1. Откройте olx.ua в обычном браузере. Найдите нужную выдачу: категория
   «Мобильные телефоны», запрос вида «iPhone 13», задайте фильтры (состояние,
   цена и т.п.).
2. Обязательно включите сортировку **«Самые новые» (наймолодші/created_at)** —
   так мониторинг видит свежие объявления первыми. В адресе появится параметр
   вида `search%5Border%5D=created_at%3Adesc`.
3. Скопируйте URL из адресной строки браузера целиком.
4. В приложении: /searches/ → «Создать» → вставьте URL в поле «URL выдачи OLX».
   Принимаются только ссылки на `olx.ua` и его поддомены — любые другие адреса
   отклоняются.
5. Заполните поля:
   - «Название» — любое понятное вам;
   - «Целевые модели» и «Память» — какие iPhone и объемы вас интересуют
     (объявления про другие модели будут отсеяны);
   - «Цена от, грн» — отсекает подозрительно дешевый мусор;
   - «Максимальная закупка, грн» — дороже этой цены не рассматривать;
   - «Минимальная прибыль, грн» и «Минимальный ROI, %» — пороги, после которых
     объявление становится кандидатом;
   - «Только частные продавцы», «Требовать OLX Доставку» — по желанию;
   - «Интервал, секунд» (не чаще 60), «Jitter, секунд», «Карточек за скан»;
   - «Включить слова» / «Исключить слова» — фильтры по тексту.
6. Сохраните. Кнопка проверки URL покажет, как приложение распознало ссылку,
   не сканируя ее.

Один и тот же URL нельзя добавить дважды — приложение сравнивает
канонизированные ссылки и сообщит «Профиль с таким URL уже существует».

Сканирование выполняется только когда мониторинг включен
(`MONITOR_ENABLED=true` в `.env`) и не стоит на паузе.

## /listings/ — Объявления

Список всех найденных объявлений с фильтрами (статус, модель, кандидат и др.).
Дубли одного и того же объявления OLX схлопываются в одну карточку, даже если
его нашли несколько поисков.

### Карточка объявления

Что видно: фото/заголовок/текст, текущая цена и **история цен**, распознанная
модель и память, детерминированный расчет: ожидаемая цена продажи, резервы,
ожидаемая прибыль и ROI (формула profit-v1), результат AI-анализа (если
включен), причины решения (почему кандидат/не кандидат).

Кнопки:

- «Открыть OLX» — открывает оригинал объявления в новой вкладке. Связываться
  с продавцом вы будете именно там, вручную;
- выбор статуса + «Сохранить» — ваше решение по объявлению;
- «Повторить AI-анализ» — поставить объявление в очередь AI заново;
- «Купил — создать сделку» — создает сделку из этой карточки;
- «Добавить рыночную цену» — если для модели еще нет рыночного правила.

### Статусы объявления

| Статус | Смысл |
|---|---|
| `NEW` | Только что найдено, никто не смотрел |
| `CANDIDATE` | Прошло пороги прибыли/ROI — стоит посмотреть |
| `REVIEWED` | Вы посмотрели и оставили в работе |
| `CONTACTED` | Вы написали/позвонили продавцу (сами, вне приложения) |
| `REJECTED` | Не подходит (отказ) |
| `SKIPPED` | Пропущено без интереса |
| `BOUGHT` | Куплено (ставится автоматически при создании сделки) |
| `SOLD` | Продано (после отметки продажи в сделке) |
| `ARCHIVED` | Убрано из работы |

Типовой рабочий цикл кандидата:
`NEW/CANDIDATE` → посмотрели (`REVIEWED`) → написали продавцу (`CONTACTED`) →
либо `REJECTED`, либо купили → «Купил — создать сделку» (статус станет
`BOUGHT`) → после продажи `SOLD`.

## /prices/ — Цены

Два справочника, на которых держится расчет прибыли.

**Рыночные цены** (правило на модель + память + SIM-вариант):

- «Ожидаемая цена продажи, грн» — за сколько вы реально продадите такой
  телефон;
- «Доставка при покупке, грн» и «Прочий резерв, грн» — постоянные издержки;
- дата проверки `checked_at` — когда вы в последний раз сверяли цену с рынком.

Кнопки: «Добавить», «Редактировать», «Деактивировать». Без активного
рыночного правила прибыль по модели не считается — объявления не станут
кандидатами.

**Резервы дефектов** — сколько вычитать из прибыли за типовой дефект
(например, «батарея 80–84%» — 900 грн, «трещина стекла» — 1200 грн). У правил
есть группа взаимоисключения (из группы применяется одно, самое приоритетное)
и приоритет.

Типовой сценарий: раз в 1–2 недели проверяйте фактические цены продажи на
OLX и обновляйте «Ожидаемую цену продажи» и `checked_at`. Если рыночная цена
устарела (старше настройки «Актуальность рыночной цены» на /settings/),
приложение это подсветит.

## /deals/ — Сделки

Учет реальных покупок и продаж. Сделка всегда создается **из карточки
объявления** (кнопка «Купил — создать сделку») — при создании сохраняется
неизменяемый снимок объявления на момент покупки.

Создание (статус фиксирован — `IN_STOCK`, «в наличии»):

- «Цена покупки, грн» (подставляется текущая цена объявления — поправьте на
  фактическую), «Дата покупки»;
- «Доставка при покупке», «Ремонт», «Прочие расходы» — можно дозаполнять позже.

Отметить проданным: откройте сделку → «Редактировать» → статус `SOLD` →
заполните «Цена продажи, грн» и «Дата продажи» → сохранить. Приложение
посчитает **фактическую прибыль** (цена продажи минус покупка, доставка,
ремонт и прочие расходы) и пометит объявление `SOLD`. Ошиблись — статус
`CANCELLED` отменяет сделку.

Кнопка «Экспорт CSV» (`/deals/export.csv`) выгружает все сделки в таблицу
для Excel/Numbers.

## /runs/ — Запуски

Журнал каждого сканирования: время, поиск, статус (`RUNNING`, `SUCCESS`,
`PARTIAL`, `FAILED`, `BLOCKED`), сколько найдено, диагностика ошибки.

Типовой сценарий: если уведомления перестали приходить — сначала сюда.
Подряд идущие `FAILED`/`BLOCKED` — смотрите docs/TROUBLESHOOTING.md.

## /settings/ — Настройки

Что видно и что можно сделать:

- **Пауза/возобновление мониторинга** — кнопки «Приостановить» и
  «Возобновить». Если OLX вернул CAPTCHA/403/429, приложение само ставит
  паузу (safety-блок): 30 минут возобновление невозможно, затем требуется
  явно поставить галочку подтверждения риска. Кнопка «Возобновить» неактивна,
  пока в `.env` стоит `MONITOR_ENABLED=false`;
- форма настроек: включение AI (работает только вместе с `AI_ENABLED=true`
  в окружении), порог уверенности для deep-модели, порог «особо выгодно»,
  актуальность рыночной цены, период перепроверки старых объявлений, сроки
  хранения журналов;
- «Отправить тест Telegram» — проверка уведомлений (см. docs/TELEGRAM_SETUP.md);
- «Проверить OpenAI-конфигурацию» — проверка настроек без обращения к OpenAI.

## /system/ — Система

Диагностика: статус воркера по heartbeat (`HEALTHY` — жив, `STALE` — отстает,
`UNAVAILABLE` — не отвечает, `NEVER_RUN` — ни разу не запускался), версия кода,
время последней очистки, счетчики. Кнопка «Предпросмотр очистки» показывает,
сколько технических записей удалила бы плановая очистка (само удаление — только
через CLI или автоматически воркером; бизнес-данные — объявления, историю цен,
сделки — очистка не трогает никогда).

## /admin/ — аварийная админка Django

Прямой доступ к таблицам базы. Используйте только когда что-то сломалось и
обычный интерфейс не помогает (например, разблокировать запись вручную).
Неосторожное редактирование здесь может испортить данные.

## Пауза и возобновление — коротко

- Пауза вручную: /settings/ или /system/ → «Приостановить» (например, уезжаете
  в отпуск или OLX ведет себя странно).
- Автопауза (safety-блок): при CAPTCHA/403/429 от OLX — 30 минут ожидания,
  затем «Возобновить» с галочкой подтверждения риска. Обходить защиту OLX
  (менять IP, ускорять интервалы, решать CAPTCHA) нельзя — это нарушение
  правил площадки и прямой путь к блокировке.
