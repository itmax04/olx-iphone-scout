# Безопасность

## Модель угроз (кратко)

Приложение — приватное, однопользовательское, с одним администратором.
Основные риски:

1. **Утечка секретов** (`.env`: ключ Django, пароль БД, ключ OpenAI, токен
   Telegram) — через случайный коммит в Git, пересылку файла или скриншот.
2. **Подбор пароля** к веб-интерфейсу, если он доступен из интернета
   (актуально для Render).
3. **Вредоносные данные снаружи**: страницы OLX и ответы внешних API — это
   недоверенный ввод; подмена URL могла бы заставить сервер ходить по чужим
   адресам (SSRF).
4. **Неожиданные расходы**: OpenAI — единственная платная интеграция.
5. **Потеря данных** — см. docs/BACKUP_RESTORE.md.

Приложение никому ничего не пишет и не проводит платежей, поэтому классов
угроз «от имени пользователя» здесь нет.

## Что уже встроено в приложение

- **Хеширование паролей Argon2** — современный алгоритм; пароль в базе не
  хранится в открытом виде.
- **Защита от перебора (django-axes)**: 5 неудачных попыток входа →
  блокировка на 15 минут (пара «логин + IP», ответ HTTP 429). Настраивается
  `AXES_FAILURE_LIMIT` / `AXES_COOLOFF_MINUTES`.
- **CSRF-защита** всех форм (стандартный механизм Django) + cookie
  `HttpOnly`/`SameSite=Lax`, сессия живет 12 часов.
- **Content Security Policy без `unsafe-inline`**: браузеру запрещено
  исполнять встроенные скрипты; все ассеты (Bootstrap, HTMX) — локальные,
  без CDN.
- **SSRF-allowlist**: приложение сканирует только `olx.ua` и его поддомены
  (`OLX_ALLOWED_HOSTS`); URL проверяется строго (поддельный
  `olx.ua.evil.com` отклоняется), DNS-резолв проверяется на публичность
  адреса.
- **Редакция логов**: фильтр логирования вырезает токены/ключи/секреты из
  сообщений, в т.ч. в JSON-формате.
- **Секреты только в `.env`**: в коде и в Git секретов нет; `.env` указан в
  `.gitignore`; бэкапы БД секретов не содержат.
- **Безопасные заголовки**: `nosniff`, `Referrer-Policy: same-origin`; в
  продакшен-настройках — secure-cookie, редирект на HTTPS, HSTS.
- **Ограниченный «пульт»**: мониторинг автоматически становится на паузу при
  CAPTCHA/403/429 (safety-блок 30 минут + явное подтверждение риска при
  возобновлении).
- **Жесткие лимиты расходов AI** (`AI_DAILY_HARD_LIMIT_USD`,
  `AI_MONTHLY_HARD_LIMIT_USD`) — предохранитель на стороне приложения,
  расходы считаются по фактическим токенам.
- **Аудит действий**: значимые действия администратора записываются в журнал
  аудита (хранится настраиваемый срок).

## Правила владельца (обязательные)

1. **Никогда не коммитьте `.env`** и не пересылайте его (почта, мессенджеры,
   скриншоты). Содержимое храните в менеджере паролей. Перед каждым
   `git commit` быстрая проверка:

```bash
git status --short
```

   В списке не должно быть `.env` и файлов из `backups/`.

2. **Репозиторий — только приватный.** Код содержит логику вашей торговли;
   даже без секретов публиковать его не нужно.

3. **2FA везде**: включите двухфакторную аутентификацию на GitHub, в OpenAI,
   в Telegram и на Render. Это самая дешевая защита от захвата аккаунтов.

4. **Ротация ключей** раз в 90 дней и немедленно при подозрении на утечку:
   `OPENAI_API_KEY` (новый project-ключ, старый удалить),
   `TELEGRAM_BOT_TOKEN` (`/revoke` у BotFather), пароль администратора
   (/accounts/password_change/). После замены значений в `.env`:

```bash
docker compose up -d --force-recreate web worker
```

5. **Сильный уникальный пароль** администратора из менеджера паролей;
   стартовый `ADMIN_PASSWORD` из `.env` смените при первом входе.

6. **Не обходите защиту OLX**: никаких прокси-ферм, решателей CAPTCHA и
   агрессивных интервалов. Safety-блок существует, чтобы вы оставались в
   рамках допустимого использования публичных страниц.

7. **Обновления**: регулярно обновляйте Docker Desktop и подтягивайте новые
   версии приложения (docs/OPERATIONS.md) — с ними приходят обновления
   зависимостей безопасности.

8. Если приложение доступно из интернета (Render) — не выключайте
   `SECURE_SSL_REDIRECT`, не расширяйте `DJANGO_ALLOWED_HOSTS` сверх нужного
   и периодически просматривайте журнал аудита и попытки входа.
