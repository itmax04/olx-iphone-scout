# Установка на macOS (подробно)

Это пошаговая инструкция для человека без опыта программирования.
Приложение целиком работает внутри Docker: на Mac не нужно ставить ни Python,
ни PostgreSQL, ни браузеры.

## 1. Установите Docker Desktop

1. Скачайте Docker Desktop с официального сайта: https://www.docker.com/products/docker-desktop/
   (выберите версию для вашего процессора: Apple Silicon или Intel).
2. Откройте скачанный `.dmg`, перетащите Docker в «Программы», запустите.
3. Дождитесь, пока в строке меню значок кита перестанет «двигаться» —
   значит Docker запущен.

Проверка (откройте Терминал: Programs → Utilities → Terminal):

```bash
docker --version
```

Где выполнять: в любом месте Терминала.
Что делает: печатает версию Docker.
Ожидаемый результат: строка вида `Docker version 27.x.x`.
При ошибке `command not found`: Docker Desktop не установлен или не запущен —
запустите приложение Docker и повторите.

## 2. Получите папку проекта

Если проект вам передали архивом — распакуйте его, например, в
`~/Documents/olx-iphone-scout`. Если проект в приватном Git-репозитории:

```bash
git clone <адрес-вашего-приватного-репозитория> ~/Documents/olx-iphone-scout
```

Где выполнять: в Терминале.
Что делает: скачивает проект в папку `~/Documents/olx-iphone-scout`.
Ожидаемый результат: папка с файлами `compose.yaml`, `manage.py`, `apps/` и т.д.
При ошибке доступа: проверьте, что у вашего GitHub-аккаунта есть доступ к
репозиторию и настроен SSH-ключ или токен.

Дальше все команды выполняются **в папке проекта**:

```bash
cd ~/Documents/olx-iphone-scout
```

## 3. Создайте файл настроек `.env`

```bash
cp .env.example .env
```

Где выполнять: в папке проекта.
Что делает: копирует шаблон настроек в рабочий файл `.env`.
Ожидаемый результат: появился файл `.env` (скрытый; в Finder нажмите
Cmd+Shift+`.` чтобы увидеть, либо откройте через TextEdit: `open -e .env`).
При ошибке `No such file`: вы не в папке проекта — выполните `cd` из шага 2.

`.env` — это личный файл с секретами. Он **не должен попадать в Git**
(он уже указан в `.gitignore`) и его нельзя никому пересылать.

### 3.1. Обязательные значения

Сгенерируйте секретный ключ Django:

```bash
openssl rand -hex 48
```

Где выполнять: в Терминале.
Что делает: печатает случайную строку из 96 символов.
Ожидаемый результат: длинная строка из букв и цифр.
При ошибке: `openssl` есть на любом macOS; если команда не найдена — обновите
macOS Command Line Tools (`xcode-select --install`).

Скопируйте строку и вставьте в `.env`:

```
DJANGO_SECRET_KEY=<вставьте-строку-сюда>
```

Сгенерируйте пароль администратора (минимум 12 символов; команда дает 24):

```bash
openssl rand -hex 12
```

Вставьте результат в `ADMIN_PASSWORD=` и запишите пароль в менеджер паролей —
он понадобится для первого входа. Также заполните `ADMIN_EMAIL=` своим e-mail.

## 4. Первый запуск

```bash
docker compose up --build -d
```

Где выполнять: в папке проекта, Docker Desktop должен быть запущен.
Что делает: собирает образ (Python, зависимости, Chromium для Playwright),
запускает 4 сервиса: `db` (PostgreSQL 17), `migrate` (одноразовый — применяет
миграции и создает администратора командой `bootstrap_admin`), `web`
(сайт на порту 8000) и `worker` (фоновый процесс мониторинга).
Ожидаемый результат: первый раз — 5–15 минут сборки, затем строки
`Started`/`Healthy` без слова `Error`. Команда возвращает управление
(флаг `-d` — «в фоне»).
При ошибке: посмотрите логи (`docker compose logs migrate web`) и найдите
ошибку в docs/TROUBLESHOOTING.md. Чаще всего: не заполнены `ADMIN_*`
(сервис `migrate` завершится с текстом `bootstrap_admin: ... required`)
или занят порт 8000.

Проверьте, что сервисы работают:

```bash
docker compose ps
```

Ожидаемый результат: `db`, `web`, `worker` в состоянии `running`
(`migrate` — `exited (0)`, это нормально: он одноразовый).

Проверьте health-эндпоинты:

```bash
curl -s http://localhost:8000/api/v1/health/live/
```

```bash
curl -s http://localhost:8000/api/v1/health/ready/
```

Что делают: `live` — жив ли веб-процесс, `ready` — доступна ли база.
Ожидаемый результат: JSON-ответ со статусом ok (HTTP 200).
При ошибке: подождите 20 секунд после запуска и повторите; затем
`docker compose logs web`.

## 5. Вход и смена пароля

1. Откройте http://localhost:8000 — вас перенаправит на страницу входа.
2. Логин — значение `ADMIN_USERNAME` из `.env` (по умолчанию `owner`),
   пароль — значение `ADMIN_PASSWORD`.
3. Сразу перейдите на http://localhost:8000/accounts/password_change/ и
   поставьте собственный пароль (из менеджера паролей).

Важно: `ADMIN_PASSWORD` из `.env` используется **только один раз** — при
создании аккаунта. После смены пароля в интерфейсе значение в `.env` больше
ни на что не влияет (команда `bootstrap_admin` никогда не меняет пароль
существующего аккаунта).

После 5 неудачных попыток вход блокируется на 15 минут — это защита от
перебора, просто подождите.

## 6. Фикстурная приемка (без интернета и без OLX)

По умолчанию `MONITOR_ENABLED=false` и `AI_ENABLED=false`, поэтому приложение
никуда наружу не ходит. Проверить весь конвейер (сбор → дедупликация → расчет
прибыли → очередь уведомлений) можно на встроенных санитизированных копиях
страниц OLX:

```bash
docker compose run --rm web python manage.py run_fixture_pipeline
```

Где выполнять: в папке проекта.
Что делает: создает тестовый поиск «FIXTURE iPhone 13 128», прогоняет через
него локальные HTML-фикстуры и печатает итоги. В OLX и OpenAI не обращается,
Telegram ничего не отправляет (записи остаются в статусе PENDING).
Ожидаемый результат: несколько строк со сводкой (`run=... status=SUCCESS`,
список объявлений, `evaluations=... outbox=...`) и в конце —
`FIXTURE_PIPELINE=PASS`.
При ошибке: команда сама откажется работать, если `MONITOR_ENABLED=true`
(выключите и повторите) или если окружение не `local`. При `FAIL` — смотрите
вывод выше строки итога и docs/TROUBLESHOOTING.md.

Повторный запуск той же команды **не создает дублей** — можно запускать
сколько угодно раз.

Сценарий «продавец снизил цену»:

```bash
docker compose run --rm web python manage.py run_fixture_pipeline --price-drop
```

Ожидаемый результат: тот же `FIXTURE_PIPELINE=PASS`; у фикстурного объявления
появится новая, более низкая цена в истории (страница /prices/ здесь ни при
чем — историю цен смотрите в карточке объявления на /listings/).

Убрать фикстурные данные, когда наиграетесь:

```bash
docker compose run --rm web python manage.py run_fixture_pipeline --cleanup-fixture-namespace
```

Что делает: удаляет только строки фикстурного пространства имен
(поиски с префиксом FIXTURE и их объявления); ваши настоящие данные не трогает.

## 7. Повторный запуск, перезапуск, остановка

Остановить все (данные в базе сохраняются):

```bash
docker compose down
```

**Никогда не добавляйте флаг `-v`**: `docker compose down -v` удаляет том
`pgdata` — то есть всю базу данных безвозвратно.

Запустить снова (без пересборки — быстро):

```bash
docker compose up -d
```

Перезапустить после изменения `.env` (Docker подхватывает `.env` только при
пересоздании контейнеров):

```bash
docker compose up -d --force-recreate web worker
```

Пересобрать после обновления кода:

```bash
docker compose up --build -d
```

Что делает: пересобирает образ и заново запускает сервисы; одноразовый
`migrate` автоматически применит новые миграции до старта `web` и `worker`.

## 8. Что дальше

- Пройдитесь по интерфейсу: docs/USER_GUIDE.md.
- Подключите Telegram-уведомления: docs/TELEGRAM_SETUP.md.
- Подключите AI-анализ (необязательно): docs/OPENAI_SETUP.md.
- Только после этого включайте мониторинг: в `.env` поставьте
  `MONITOR_ENABLED=true`, выполните `docker compose up -d --force-recreate web worker`
  и следите за /system/ и /runs/.
