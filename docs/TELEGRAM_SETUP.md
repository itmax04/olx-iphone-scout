# Подключение Telegram-уведомлений

Приложение отправляет уведомления о кандидатах и снижениях цен в личный чат
с вашим собственным Telegram-ботом. Бот **только отправляет** сообщения вам;
никому другому он не пишет и команды не принимает.

Понадобится 10 минут и приложение Telegram.

## Шаг 1. Создайте бота у @BotFather

1. В Telegram найдите официального бота `@BotFather` (синяя галочка).
2. Отправьте ему команду `/newbot`.
3. Придумайте имя (любое, например «Мой iPhone Scout») и username бота
   (должен оканчиваться на `bot`, например `my_iphone_scout_bot`).
4. BotFather пришлет **токен** вида `1234567890:AAAA...` — это секрет.
   Никому не показывайте и не отправляйте его. Если токен утек — в BotFather
   команда `/revoke` выдает новый.

## Шаг 2. Впишите токен в `.env`

Откройте `.env` в папке проекта (например, `open -e .env`) и заполните:

```
TELEGRAM_BOT_TOKEN=<токен-от-BotFather>
```

`TELEGRAM_CHAT_ID` пока оставьте пустым — узнаем на шаге 4.

## Шаг 3. Отправьте боту /start

В Telegram откройте чат со своим новым ботом (по username) и отправьте ему
сообщение `/start`. Это обязательный шаг: Telegram разрешает боту писать
только тем, кто первым начал с ним диалог.

## Шаг 4. Узнайте свой chat ID

```bash
docker compose run --rm web python manage.py discover_telegram_chat_id
```

Где выполнять: в Терминале, в папке проекта, при запущенном Docker Desktop.
Что делает: спрашивает у Telegram, кто писал боту, и печатает ID чатов.
Токен и тексты сообщений команда никогда не печатает.
Ожидаемый результат: строка вида

```
TELEGRAM_CHAT_ID=123456789  (@ваш_username)
```

При ошибке:

- `TELEGRAM_BOT_TOKEN не задан` — заполните шаг 2 и повторите (если
  контейнеры уже работали, перезапустите их, см. шаг 5);
- `No chats found` — отправьте боту `/start`, подождите 5 секунд, повторите;
- `У бота настроен webhook` — у бота ранее настраивали webhook; удалите его
  (в стороннем сервисе, где настраивали) и повторите;
- `Не удалось обратиться к Telegram` — проверьте интернет и правильность токена.

## Шаг 5. Впишите chat ID и перезапустите

Добавьте в `.env`:

```
TELEGRAM_CHAT_ID=<число-из-шага-4>
```

Перезапустите контейнеры, чтобы они увидели новые переменные:

```bash
docker compose up -d --force-recreate web worker
```

Где выполнять: в папке проекта.
Что делает: пересоздает сервисы `web` и `worker` с новым `.env`.
Ожидаемый результат: оба контейнера в состоянии `running` (`docker compose ps`).
При ошибке: `docker compose logs web worker` и docs/TROUBLESHOOTING.md.

## Шаг 6. Проверьте отправку

Вариант А — из Терминала:

```bash
docker compose run --rm web python manage.py send_test_telegram
```

Что делает: создает запись в очереди уведомлений (outbox) и сразу отправляет
тестовое сообщение.
Ожидаемый результат: в Терминале — `Тестовое сообщение отправлено.`,
в Telegram — сообщение от вашего бота.
При ошибке `Telegram не настроен` — проверьте оба значения в `.env` и
перезапуск из шага 5. При `Отправка не удалась` — см. таблицу в
docs/TROUBLESHOOTING.md (обычно неверный токен — 401, или неверный chat ID —
"chat not found").

Вариант Б — из интерфейса: страница /settings/ → кнопка
**«Отправить тест Telegram»**. Зеленое сообщение «Тестовое сообщение
отправлено в Telegram» + сообщение в чате = все работает.

## Как это работает дальше

Уведомления идут через transactional outbox: сначала запись сохраняется в
базе, потом воркер ее отправляет. Если Telegram временно недоступен, записи
ждут в очереди и досылаются позже — ничего не теряется. Статусы очереди видны
на /system/, застрявшие FAILED-записи — повод заглянуть в
docs/TROUBLESHOOTING.md.
