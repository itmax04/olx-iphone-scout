# Бэкапы и восстановление

В базе данных живет все ценное: объявления, история цен, оценки, сделки,
настройки. Контейнеры и код восстанавливаются за минуты, база — только из
бэкапа.

## Политика бэкапов (минимум)

- **Перед каждым обновлением версии** — обязательно.
- **Раз в неделю** при активной работе, раз в месяц — при пассивной.
- Раз в квартал — **проверка восстановления** (бэкап, который ни разу не
  восстанавливали, — это не бэкап, а надежда).
- Храните последние 4–8 файлов; хотя бы одну копию — вне этого компьютера
  (внешний диск/облако). Файл `.env` в бэкап **не входит** — храните его
  содержимое в менеджере паролей отдельно.

## Сделать бэкап

```bash
./scripts/backup_local.sh
```

Где выполнять: в Терминале, в папке проекта, контейнер `db` должен работать
(`docker compose ps`).
Что делает: снимает дамп PostgreSQL и кладет в папку `backups/` три файла:
сам дамп `*.dump`, контрольную сумму `*.sha256` и manifest с описанием.
Секреты (`.env`) в бэкап не попадают.
Ожидаемый результат: новые файлы в `backups/` (проверьте: `ls -lh backups/`),
скрипт завершился без ошибок.
При ошибке «db is not running»: сначала `docker compose up -d`, затем повторите.

## Проверить восстановление (раз в квартал)

Восстановление выполняется **только в отдельную пустую тестовую базу** —
никогда поверх рабочей.

1. Создайте пустую тестовую базу внутри контейнера `db`:

```bash
docker compose exec db createdb -U iphone_scout iphone_scout_restore_test
```

Где выполнять: в папке проекта.
Что делает: создает пустую базу `iphone_scout_restore_test` рядом с рабочей.
Ожидаемый результат: команда молча завершается (без вывода).
При ошибке `already exists`: тестовая база осталась от прошлой проверки —
удалите ее (`docker compose exec db dropdb -U iphone_scout iphone_scout_restore_test`)
и повторите. Внимательно: `dropdb` — только для `iphone_scout_restore_test`,
ни в коем случае не для `iphone_scout`.

2. Восстановите последний дамп в тестовую базу (подставьте имя своего файла):

```bash
./scripts/restore_local.sh backups/<файл>.dump iphone_scout_restore_test
```

Что делает: проверяет контрольную сумму и загружает дамп в указанную базу.
Скрипт принимает только пустую тестовую базу — восстановить поверх рабочей
он не даст.
Ожидаемый результат: сообщение об успешном восстановлении без ошибок.
При ошибке несовпадения контрольной суммы: файл поврежден — используйте
другой бэкап и проверьте диск/облако, где он хранился.

3. Выборочно проверьте данные (например, число объявлений):

```bash
docker compose exec db psql -U iphone_scout -d iphone_scout_restore_test -c "SELECT count(*) FROM monitoring_listing;"
```

Ожидаемый результат: число, похожее на количество объявлений на момент бэкапа.

4. Удалите тестовую базу:

```bash
docker compose exec db dropdb -U iphone_scout iphone_scout_restore_test
```

## Главное предупреждение

```bash
docker compose down
```

— безопасно: останавливает контейнеры, база остается в томе `pgdata`.

**`docker compose down -v` — ЗАПРЕЩЕНО.** Флаг `-v` удаляет тома вместе с
базой данных. Никакая «уборка» и никакой совет из интернета не оправдывают
эту команду на рабочей машине. Если очень нужно пересоздать базу с нуля —
сначала бэкап, потом дважды подумайте.

Той же осторожности требуют `docker system prune --volumes` и удаление томов
в интерфейсе Docker Desktop.

## Аварийное восстановление рабочей базы

Если рабочая база погибла (диск, случайное удаление):

1. Поднимите чистую базу: `docker compose up -d db`.
2. Восстановите дамп в **новую** базу тем же `restore_local.sh`.
3. Переключите `DATABASE_URL` в `.env` на эту базу и
   `docker compose up -d --force-recreate web worker migrate`.

Если не уверены в шагах — сначала потренируйтесь на тестовой базе, как
описано выше; сами шаги идентичны.

## Render (облако): PITR

Если приложение развернуто на Render (docs/DEPLOY_RENDER.md), у управляемой
базы PostgreSQL есть point-in-time recovery — восстановление на любой момент
за последние дни (срок зависит от тарифа). Это делается в панели Render:
Database → Recovery. PITR дополняет, но не заменяет ваши локальные дампы:
экспортируйте дамп с Render хотя бы раз в месяц и храните у себя.
