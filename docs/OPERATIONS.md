# Регулярные операции

Приложение спроектировано так, чтобы требовать минимум внимания, но раз в
неделю и раз в месяц стоит выполнять короткий ритуал проверки.

## Еженедельно (10 минут)

### 1. Проверка /system/

Откройте /system/ и убедитесь:

- статус воркера — `HEALTHY` (heartbeat свежее 90 секунд). `STALE` /
  `UNAVAILABLE` / `NEVER_RUN` — воркер не работает: смотрите логи (ниже) и
  docs/TROUBLESHOOTING.md;
- нет незнакомого safety-блока (если мониторинг стоит на паузе из-за
  CAPTCHA/403/429 — это видно здесь и на /settings/).

### 2. Неудачные запуски

Откройте /runs/ и отфильтруйте по статусам `FAILED` и `BLOCKED`.
Единичные `FAILED` — нормально (сеть моргнула). Серии подряд — проблема:
откройте диагностику запуска и сверьтесь с docs/TROUBLESHOOTING.md.

### 3. Застрявшие уведомления (outbox FAILED)

На /system/ проверьте счетчики очереди уведомлений. Если есть записи в
статусе `FAILED` — Telegram-уведомления не доходят: проверьте
`TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID` и отправьте тест с /settings/.

### 4. Актуальность рыночных цен

Откройте /prices/. Для каждой активной модели сверьте «Ожидаемую цену
продажи» с реальными ценами продажи на OLX и обновите правило (и дату
проверки). Устаревшие цены = неправильная ожидаемая прибыль = ложные
кандидаты или пропущенные выгодные объявления.

## Ежемесячно (30 минут)

### 1. Расходы AI

На /dashboard/ проверьте расходы AI за месяц — они должны быть заметно ниже
`AI_MONTHLY_HARD_LIMIT_USD`. Если лимит выбивается в первые дни месяца —
уменьшите поток (меньше поисков/карточек) или поднимите порог эскалации.

### 2. Бэкап и проверка восстановления

См. docs/BACKUP_RESTORE.md — минимум раз в месяц делайте бэкап и раз в
квартал проверяйте, что он восстанавливается.

### 3. Ротация ключей

Раз в 90 дней меняйте `OPENAI_API_KEY` (docs/OPENAI_SETUP.md) и при
необходимости `TELEGRAM_BOT_TOKEN` (`/revoke` в BotFather). После замены:

```bash
docker compose up -d --force-recreate web worker
```

### 4. Очистка старых технических данных

Очистка удаляет **только техническое**: старые записи журнала запусков,
аудита, журналов защиты входа и истекшие сессии. Объявления, история цен,
AI-результаты, уведомления и сделки не удаляются никогда. Воркер выполняет
очистку автоматически раз в день; вручную она нужна редко.

Посмотреть, что было бы удалено (ничего не удаляет):

```bash
docker compose run --rm web python manage.py cleanup_old_data --dry-run
```

Где выполнять: в папке проекта.
Ожидаемый результат: счетчики по категориям (scan_runs, audit_events,
axes_logs, sessions).
При ошибке: см. логи; тот же предпросмотр доступен кнопкой на /system/.

Выполнить очистку:

```bash
docker compose run --rm web python manage.py cleanup_old_data --confirm
```

Сроки хранения настраиваются на /settings/ («Хранить журнал запусков, дней»,
«Хранить аудит, дней»); неудачные запуски хранятся минимум 180 дней.

## Обновление версии приложения

Выполняйте, когда в репозитории появилась новая версия кода.

1. Сначала сделайте бэкап (docs/BACKUP_RESTORE.md).

2. Получите новый код:

```bash
git pull
```

Где выполнять: в папке проекта.
Ожидаемый результат: список обновленных файлов или `Already up to date.`
При ошибке про локальные изменения: не редактируйте файлы проекта вручную;
если редактировали — разберитесь с изменениями до обновления.

3. Пересоберите и перезапустите (миграции применит одноразовый сервис
`migrate` автоматически, до старта web и worker):

```bash
docker compose up --build -d
```

Ожидаемый результат: сборка завершилась, `docker compose ps` показывает
`db`, `web`, `worker` в `running`, `migrate` — `exited (0)`.
При ошибке миграций: `docker compose logs migrate`; приложение не стартует
на несмигрированной базе — восстановите бэкап и вернитесь на прежнюю версию
кода (`git checkout <прежний-тег>`), затем разбирайтесь.

4. Проверьте:

```bash
curl -s http://localhost:8000/api/v1/health/ready/
```

и откройте /system/ — версия кода и статус воркера.

## Просмотр логов

Последние события всех сервисов:

```bash
docker compose logs --tail=100 web worker
```

Следить в реальном времени (выход — Ctrl+C):

```bash
docker compose logs -f worker
```

Только ошибки веб-сервера:

```bash
docker compose logs web | grep -i error
```

Логи автоматически редактируются: токены, ключи и другие секреты в них
заменяются заглушками. Тем не менее не публикуйте логи целиком в открытых
местах.

## Пауза на время отпуска

Перед длительным отсутствием: /settings/ → «Приостановить». Контейнеры можно
оставить работающими или остановить:

```bash
docker compose down
```

(данные сохраняются; **никогда** не используйте флаг `-v`). По возвращении —
`docker compose up -d` и «Возобновить» на /settings/.
